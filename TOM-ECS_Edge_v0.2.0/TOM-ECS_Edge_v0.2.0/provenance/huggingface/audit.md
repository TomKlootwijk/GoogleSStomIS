## Reused implementation

The discovery changed the implementation approach: TNOMTOM already has the sought source-family integration and XD-ECS V11. Its full host/compiler is a substantial JavaScript/Wasm/history suite. A new unrelated generic transition engine would not be a faithful substitute.

The public inventory pins above and the assembly's compatibility lineage are distinct. Each native profile's `source_revision` intentionally points to the TNOMTOM assembly commit, whose own recipes bind their exact modules and initializers. Its embedded source lock can predate the separately listed repositories. The application does not silently replace those compatible inputs with newer repository files or claim that every latest edit is present in an older assembly profile.

The concrete Android integration therefore translates six **existing, pinned Wasm kernels** to C, with eight unchanged admitted recipes. Their source names, exact type domains, initializers, status codes and finite capacities remain visible. The native table, artifacts, full-memory goldens and limitations are in `../../native_modules/README.md` and `../../native_modules/source_manifest.json`. The independent direct TOMK bridge also retains the unchanged original C implementation and MIT notice.

The source's use of computational-data bit-LUTs is narrower than a whole-CPU one-bit claim: control, indexing, addresses, extraction and transport remain conventional native operations. Full XD-ECS/11 actor/history/compiler compatibility, every source operator and arbitrary physical interpretations are outside these selected profiles. The containing ECS event/receipt wrapper is new integration code, and its demonstrated paired u64 rule is a separately named example rather than a replacement for source Maktub equations.

Both original state action and description rewrite consume the same pre-event snapshot. In Pinion, an old row acts before its overlay changes for later execution. In MaktubIII, old alpha and gate descriptions drive the current paired action; requested descriptions are future state. Exact rational/algebraic later profiles do not imply byte identity with the original floating-point implementations. These distinctions are encoded in the selected recipe metadata rather than collapsed into a universal rule.

## Documents and datasets in the app

`../../assets/documents/source_cards.json` contains 132 bounded retrieval records: the original 20 curated records; all 50 supplied Lognet PDF pages; all nine supplied Google-export pages; all ten pinned Hugging Face README cards; two parsed dataset fixture references; and eight executed native-profile descriptions. `corpus_validation.json` records its exact size and hash. Source IDs, page numbers, original file hashes, README commit URLs and separate status labels travel with the excerpts. Each body is at most 3,000 UTF-8 bytes, and the complete rendered record stays within the history store's 4,096-byte input limit.

Personal ID/date and hardware identifiers are masked in the searchable derivative text; source hashes bind the original supplied files. Source content is explicitly data, not instructions for the assistant. The Google conversation remains generated, unverified discussion. Mathematical source definitions, parsed references and host-executed tests carry different labels.

Both dataset repositories contain the **same** `kernel/docs/seed-inputs.json` bytes, SHA-256 `9c52c3bc286e108f67c8e1124316d6c058b84c440c9327fb332e617c75c8756b`. Their fixture defines NFC/UTF-8 text, SHA-256 and a low-bit-first schedule indexed by `(logical_tick + global_chain_id) mod 256`. A nonpersonal record was parsed and independently hash-checked in `dataset_seed_reference.json`. The original ABI files also match exactly across the datasets. These are reusable reference artifacts with two provenance bindings, not two distinct training corpora. The native default Pinion recipe still uses its explicit event value 1; a fixture does not silently change execution.

## Evidence limits and rights

Every downloaded executable source was inspected before selected execution. The original NativeRecipeKernel and six Wasm binaries were used as the comparison oracle; no downloaded repository setup scripts or dependency hooks were run. The source README's larger upstream test counts are author evidence, not newly performed tests. Our reported counts are recorded separately under native-module tests and the ECS tests.

Public access does not itself grant an open-source license. TOMK publishes MIT terms; the twin repositories retain their particular notices; TNOMTOM explicitly reserves rights. The owner-directed build preserves those notices without assigning a new license or publishing the source to a new service. WABT's Apache 2.0 license applies to the translation runtime, not to the author's kernels.
